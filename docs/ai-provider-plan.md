新增 Android Keystore AES-256-GCM 存储，文件位于应用的 `noBackupFilesDir`，使用临时文件后替换。界面状态只暴露凭据存在标记；读取/解密错误不会静默覆盖原配置。保存成功才更新“未配置”状态。更换提供商或配置后，新对话不会自动携带旧提供商的聊天记录。

协议路径、工具响应过滤、凭据隔离、保存失败和取消请求测试已通过。恢复构建后，原生工程单元测试共 100 项、0 失败、0 错误。原生 API 设置页与聊天页已接入；Android 14 模拟器验证了 Keystore 加密保存、重启读取、密码字段不回填和“未配置”标记消失。验证只使用虚构模型和凭据，未请求真实服务、未验证真实账户。详见 `native-validation.md`。

当前 Android 网络策略仅允许本机回环 Ollama 使用 HTTP；远端及局域网服务使用 HTTPS。配置校验与系统策略一致，避免保存实际不能连接的 HTTP 局域网地址。

## 不可跨越的执行边界

- AI 仅聊天、命令推荐、风险提醒、测试建议，以及分析用户主动提供的信息。
- AI 模块不依赖 RootManager、Shell、内核接口、设备控制或无障碍。
- 不声明执行工具；返回的 tool_calls、function_call、Shell 指令是数据，不进入执行路径。
- AI 页面只支持复制推荐内容，不提供执行按钮。不把“确认”做成连接 AI 与 Root 的自动通道。
- Comput 是分离的手动终端；AI 不可替用户写入待执行任务或启动终端操作。
- 连接/模型测试只测试服务，不执行设备命令，不自动上传日志、标识、镜像和模块。

## 配置保护与测试

- Android Keystore 加密用户自带凭据，排除自动备份与配置导出中的密钥。
- 无应用内置共享供应商密钥；商业服务优先支持代理/短期凭据，而不是把服务端密钥分发到 APK。
- 保存配置不自动发请求；测试按钮明确说明是否消费额度。
- 公网使用 HTTPS；本地 Ollama 的 HTTP 例外需用户明确选择并限制作用范围。
- 切换提供商不转发旧提供商凭据；重定向不能把 Authorization 带到陌生域名。
- 超时、取消、网络失败、限流、认证失败和响应格式错误可见；不无限重试。
- 日志与崩溃记录不包含密钥或认证头。对话是否保存/导出由用户控制。
- 连接测试、聊天与建议均无任何 Root/设备执行路径。
